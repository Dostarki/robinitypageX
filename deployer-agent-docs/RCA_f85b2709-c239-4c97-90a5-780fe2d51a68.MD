# RCA — robinit.xyz serves the Emergent placeholder after redeploy

## Verdict
The live site is NOT broken by a failed deploy, a domain/DNS/SSL problem, or missing secrets.
It is an **architecture / frontend-directory mismatch**. The deployment template only ever
builds and serves `/app/frontend`, and `/app/frontend` still contains the **stock Emergent
placeholder**. The real app in `/app/robinitypage` (custom `serve.js` on port 3000) is never
built, run, or served by this pipeline.

## Deployment facts
- Deployment: `robinity-preview` | template: `fastapi_react_mongo_shadcn_base_image` (FARM) | `frontend_type: cloudflare` | tier_0
- Latest run `f85b2709-c239-4c97-90a5-780fe2d51a68` (redeploy) = **SUCCESS** (21:50→21:55Z). Build SUCCESS, image pushed, frontend synced to R2, promoted. So "not live" is NOT a pipeline failure.

## 1. Pipeline status — HEALTHY
Build state SUCCESS. `frontend-build` stage compiled a standard CRA and produced exactly 7 files
(`index.html`, `static/js/main.d27146cd.js`, `static/css/main.bc058c4f.css`, …) which were synced to
`s3://deployer-frontend-artifacts/robinity-preview/<run>/build/` and served by Cloudflare. Nothing
is still building or failed.

## 2. Domain / routing / SSL — HEALTHY, correctly bound
- `robinit.xyz` and `www.robinit.xyz`: `verified: true` and DNS A-record check `linked: true`.
- The placeholder is being served BY this deployment's own (stock) frontend — it is NOT an
  "unbound / not-yet-live" holding page. The domain is pointing at the right deployment; that
  deployment is simply serving the wrong (placeholder) frontend.

## 3. ROOT CAUSE — wrong frontend directory / non-conforming architecture
The FARM + Cloudflare template contract:
- Build stage builds **`/app/frontend`** only (CRA/Vite) → output (`build/` or `dist/`) is pushed to R2 → Cloudflare serves those static assets. `/api/*` routes to the K8s backend (FastAPI :8001 behind nginx :8080).
- There is **no port-3000 process** in the runtime image. `/app/robinitypage/serve.js` is never started.

Confirmed in the pulled source (eph sandbox, run f85b2709):
- `/app/frontend/src/App.js` = **stock placeholder**: `<div data-emergent-splash>` … `<p>Building something incredible ~!</p>` + Emergent logo; `public/index.html` title `Emergent | Fullstack App`. This is precisely the page live on robinit.xyz.
- `/app/robinitypage/` exists with `serve.js` (custom static server, port 3000, SPA fallback to `app/web/index.html`) and `package.json` scripts `build:web` → `node scripts/build-web.js` (esbuild → `app/web/dist`). **None of this is referenced by the Dockerfile.cloudbuild, build-frontend-artifacts.sh, or entrypoint.sh.**
- `/app/frontend/.env` `REACT_APP_BACKEND_URL=https://robinity-preview.preview.emergentagent.com` is irrelevant to prod — the pipeline overrides it to `https://robinit.xyz` at build time (seen in build log).

Net: the app was developed as a bespoke Node-served site under `/app/robinitypage`, but the
deployment builds/serves `/app/frontend`, which was left untouched as the placeholder.

## 4. Production secrets — all present (values not overwritten on redeploy)
Present and non-empty: `X_CLIENT_ID`, `X_CLIENT_SECRET`, `X_REDIRECT_URI`, `MONGO_URL`, `DB_NAME`,
`CORS_ORIGINS`, `FRONTEND_URL`, `INTEGRATION_PROXY_URL`, `REACT_APP_BACKEND_URL`, `WDS_SOCKET_PORT`,
`X_DEV_MOCK`, `X_QUOTE_TEXT`, `X_TARGET_USERNAME`.
- `X_REDIRECT_URI` value **matches** `https://robinit.xyz/api/x/auth/callback` ✅
- `REACT_APP_BACKEND_URL` value **matches** `https://robinit.xyz` ✅
- `X_TASK_TWEET_URL` is present but **EMPTY** — set it if the app needs it.
- **No dedicated JWT/session secret key exists** in production (nothing named `JWT_SECRET` /
  `SESSION_SECRET` / similar). If the app signs sessions/JWTs, that key is missing — add it to
  preview `.env` and redeploy (new keys are picked up on deploy; existing values are never
  overwritten).

Secrets are fine and are NOT the cause of the placeholder.

## Fix (E1 / source-level — I did NOT change source or manifests)
The app must conform to what the FARM+Cloudflare template builds. Pick one:

**Option A (recommended, template-conformant):** Make `/app/frontend` the real app.
Port the robinity UI into `/app/frontend` as the standard CRA/craco build so `yarn build` emits the
real site. serve.js is not needed in prod — Cloudflare already serves the static assets and does
SPA fallback (equivalent to serve.js's `try_files → index.html`).

**Option B:** Make the frontend build emit robinity's static output into `/app/frontend`'s build
output dir (`build/` or `dist/`). Since the pipeline only ships the static build artifacts to R2,
the goal is simply: `/app/frontend` build produces robinity's compiled static site (from
`npm run build:web` / esbuild), with asset paths that resolve at site root. Verify `index.html`
references hashed assets with correct base paths.

Either way, after restructuring, redeploy — the build will push the real assets to R2 and Cloudflare
will serve the actual app. A manifest-only fix was deliberately NOT attempted: the app does not
conform to the template contract, and redirecting the build to `/app/robinitypage`'s bespoke esbuild
output would be speculative (unverified output layout/asset paths) and still would not run serve.js.

## Not the cause (ruled out)

- Domain binding, DNS, SSL all correct.
- Backend secrets present with correct X OAuth callback + backend URL values.
